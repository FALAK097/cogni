---
title: Agent configuration, testing, and deployment
description: Configure the agent in Build, validate drafts in Test, and publish versions from Deploy.
---

The Agent area is divided into **Build**, **Test**, and **Deploy**. Draft configuration remains separate from the version currently serving visitors until an owner publishes it.

## Build

Choose the model provider and model, then configure:

- the public agent name and instructions;
- keywords that request a human handoff;
- response behavior, visitor input placeholder, and suggestion behavior;
- lead capture timing and trigger keywords;
- brochure availability and button label;
- the privacy-policy URL; and
- booking availability and the approval flow.

Knowledge content is managed separately in **Knowledge**. The agent retrieves ready sources when answering rather than treating the instruction field as a content repository.

## Test

The preview runs the current draft without changing the live widget. Ask representative questions and inspect the response, source evidence, and handoff evidence.

Save repeatable test cases for important journeys. Test runs keep history, and the publish flow can compare the current draft with the published configuration before release.

## Publish

Open **Deploy** to review readiness, enable the agent, configure the widget and authorized domains, and publish. Only workspace owners can publish.

A publication captures the deployable agent, knowledge, widget, and booking configuration. The website widget continues to use its existing published version until a new publication succeeds.

## Restore a version

Version history lists previous publications. Restoring creates a new publication from the selected snapshot; it does not rewrite earlier history. Review the restored configuration and live-domain settings before sending visitor traffic to it.
